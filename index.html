01

Target · Supply chain · 2026–now

Event-driven pipelines for warehouse replenishment

Replenishment and pack data has to move between warehouse systems, internal platforms and third-party services, and every event has to arrive exactly once.

Context

Outbound replenishment

I'm on the team that decides what gets packed and shipped from distribution centers, a high-volume, always-on workload.

Problem

Lost or duplicated events cost money

A dropped event leaves demand unfilled; a duplicate over-packs. Bad messages can't be allowed to stall a whole partition.

Approach

Design for failure

  • Kafka producers, consumers and Streams with exactly-once semantics
  • Dead-letter queues for poison messages
  • GCP Pub/Sub across services, BigQuery for analytics

Result

Traceable, fault-tolerant flow

OpenTelemetry tracing and Grafana dashboards follow each event end to end, so issues are found fast. Every change ships through tested, SonarQube-gated CI.

Exactly-onceProducers write to a partitioned topic; consumers in one group share the partitions; failures are retried, then dead-lettered.

02

Deloitte · HDFC Bank · 2020–2022

Cutting critical banking reports by 40%

End-of-day settlement depended on reports that ran over very large transactional datasets, and they were too slow.

Context

Transaction processing at scale

A large financial platform handling rule execution, validation and case management for banking transactions.

Diagnose

Read the execution plans

Instead of guessing, I traced where time went in the Oracle queries and stored procedures behind each report.

Fix

Change the data path

  • Redesigned indexes for the real access patterns
  • Partitioned the heaviest tables
  • Refactored stored procedures to process in batches

Result

40% faster reports

Critical report generation dropped by 40%. Separately, migrating key services from Java to Kotlin cut code volume by 30%.

03

Charter Communications · 2024–2026

From synchronous chains to event-driven services, plus AI

Critical workflows were coupled through synchronous calls, so one slow service slowed everything behind it.

Problem

Tight coupling

Services waited on each other in critical paths, which hurt throughput under heavy concurrent load.

Approach

Decouple with events

  • Kafka Producer/Consumer/Streams pipelines
  • Non-blocking Kotlin coroutine services
  • Plugin-style rule-engine components

Quality

Secure and tested

OAuth 2.0, JWT and Spring Security across services, with 85%+ test coverage and SonarQube scans in CI.

AI

LLM features in production code

RAG pipelines, vector search, summarization and data extraction with OpenAI APIs, LangChain and Hugging Face.

AsyncServices publish and move on, instead of waiting in a chain.
